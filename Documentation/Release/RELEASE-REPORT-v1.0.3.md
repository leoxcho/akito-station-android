# Android v1.0.3 release verification

Package app.akitostation.android; versionName 1.0.3; versionCode 4. The macOS project was not modified. Android source was prepared from the published v1.0.2 baseline.

Bulk box-art scraping: Games → Scrape Box Art offers Missing Artwork Only by default; All Games defaults to keeping existing artwork, with explicit replacement available. Uses existing online-artwork consent and Libretro Thumbnails catalogs only. All currently mapped catalog platforms are supported independently of runtime adapters. Catalogs are fetched and searched locally; automatic application requires exact normalized title and platform equality. Region combinations such as USA, Europe normalize consistently with manual search. Sequel/subtitle/other-system substitutions are rejected; unsupported and unmatched titles remain unchanged. No fuzzy-confidence claims are made. Region variants are chosen deterministically, and variants with additional unrecognized tags require manual review.

One game is processed at a time on the IO dispatcher. Temporary I/O, 429 and server failures receive up to two bounded retries and backoff. Catalogs are cached per run; repeated image URLs reuse installed files, and identical artwork shares a content-hash file. Artwork is raster-validated and installed atomically; prior image files are retained. Concurrent manual edits are rechecked before installation. Progress, cancellation, summary and Review Missing Artwork are implemented. Completed covers remain after cancellation/interruption. Process death does not automatically resume work; rerunning missing-only skips completed covers. Background execution is best effort, not a persistent worker. An in-flight blocking network operation can take its bounded timeout before cancellation finishes.

Live provider validation: a synthetic Pokemon - Emerald Version library record received a decodable, persisted cover through bulk scraping on both phone and tablet, without opening each game. Existing manual search/select/apply and immediate refresh passed on both. These are representative live matches, not a compatibility/completion percentage for a real user library.

Library grid-size selector: Games → View / Grid Size and Settings → Library view share 2×2, 3×3, 4×4, 5×5 and 6×6. Presets target 280, 210, 160, 120 and 96dp card widths. Columns adapt to width and font scale, without horizontal library scrolling. Card width also changes when adjacent presets share a column count on a narrow screen. 4×4 preserves the old normal target; old Compact users migrate to 5×5. Selection applies immediately, is stored in existing station preferences, and is independent of search, Favorites, Recently launched and system filtering. Cards retain proportional fitted artwork, two-line titles, 48dp minimum touch targets and stable lazy item keys. Density changes restore the most recently focused game's position/focus when that game remains in the active grid.

Accepted tests: 155 JVM tests, zero failures/errors/skips, including the full existing suite, API 26/35 persistence, matching/rejection, modes, counters, consent, retry, cancellation, deduplicated storage and update selection. Phone 13/13 and tablet 13/13 final UI cases passed on an isolated ARM64 API 36 emulator: phone 1080×1920 at 420dpi; tablet 1600×1920 at 240dpi. Phone preference testing initially had ambiguous menu selectors and was corrected/revalidated; those failures were in test selectors. The tablet complete 12-case suite plus an additional D-pad grid-menu selection test passed; phone's 11 non-preference cases, corrected preference case and additional menu case passed. Covered all five modes, immediate changes, activity recreation, shared filtered views, D-pad menu/select and game focus, scrolling a 10,000-record synthetic library through all presets, live bulk/manual covers and no overlapping card bounds at 6×6. This is functional scrolling validation, not a frame-time benchmark or physical-controller/device test. Production phone/tablet 6×6 screenshots were inspected for fitted artwork and readable titles/badges.
